## 1. Objectives & Scope Delivered

1. **Áreas Tab Experience (Tab 3 in `EquipoModal.tsx`)**:
   - **Zero Areas State**:
     - Displays informative empty state (`data-testid="empty-areas-state"`) communicating that areas are optional and used to group employees/planners by branch or department.
     - Provides clear CTA "+ Crear primera área" (`data-testid="create-first-area-button"`).
   - **Organization with Areas**:
     - Dedicated toolbar with "+ Nueva área" CTA (`data-testid="create-area-button"`).
     - Full table listing (`data-testid="areas-table"`):
       - Name & code badge
       - Status badge (`Activa` / `Inactiva`)
       - Active employee count
       - Assigned planner count
       - Action: "Editar" (`data-testid="edit-area-${id}"`) opening Area Modal
       - Action: "Gestionar asignaciones" (`data-testid="manage-area-assignments-${id}"`) navigating directly to Asignaciones tab
   - **Area Modal** (`data-testid="area-modal"`):
     - Handles creation and updating of areas with server-side validation.
     - Inputs for Name (`data-testid="area-name-input"`), Code (`data-testid="area-code-input"`), and Active checkbox (`data-testid="area-active-checkbox"`).
     - Submits to `createRemoteArea` / `updateRemoteArea` and refreshes both local areas and parent dashboard context (`onChanged()`).

2. **Planner Scopes Management (Tab 2 in `EquipoModal.tsx`)**:
   - Implemented 3 planner scope modes:
     1. `ORGANIZATION`: Entire organization (`data-testid="scope-radio-org"`).
     2. `AREAS`: Specific areas (`data-testid="scope-radio-areas"`) with multi-select checkboxes (`data-testid="scope-area-${id}"`).
     3. `EMPLOYEES`: Specific employees (`data-testid="scope-radio-employees"`) with search input (`data-testid="scope-employee-search"`), dynamic counter (`data-testid="scope-selected-employees-count"`), and checkboxes (`data-testid="scope-employee-${id}"`).
   - Wired scope updates through `updateRemoteMemberRole` with `plannerScopeType`, `scopedAreaIds`, and `scopedEmployeeIds`.

3. **Backend API Area Support (`api/areas/index.js`)**:
   - Enhanced `PATCH /api/areas` to support `active` boolean and `reactivate: true` alongside existing `deactivate: true`, keeping fake SQL mock and production query structures backward-compatible.
   - Added unit test in `api/areas/index.test.js` verifying area reactivation.

4. **i18n Parity (`src/lib/i18n.ts`)**:
   - Added area and planner scope keys in Spanish and English under `teamWorkspace` namespace.
   - Structural coverage passed 100% via `src/lib/i18n-coverage.test.ts`.
