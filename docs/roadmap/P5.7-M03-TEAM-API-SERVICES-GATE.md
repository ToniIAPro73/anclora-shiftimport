## 1. Objectives & Scope Delivered
1. **Ownership Transfer Endpoint (`POST /api/organizations/transfer-ownership`)**:
   - Sole Owner transfers organization ownership to another active member.
   - Updates target member to `OWNER`.
   - Transitions former owner to `ADMIN` (or `PLANNER` if specified).
   - Enforces invariant: Exactly one active OWNER per organization.
   - Clears prior planner scopes on both parties.
   - Transactional execution and audited via `organization_audit_events` (`OWNERSHIP_TRANSFERRED`).

2. **Operational Assignments API (`/api/assignments`)**:
   - `GET /api/assignments`: Lists active operational assignments with filters for `assignmentType`, `subjectId`, `targetId`.
   - `POST /api/assignments`: Creates or transitions assignment with effective dating (`valid_from = effectiveDate`, closes prior assignment `valid_to = effectiveDate`). Supports `EMPLOYEE_AREA`, `PLANNER_AREA`, `PLANNER_EMPLOYEE`. Synchronizes legacy `employees.area_id` and `memberships.scoped_area_id` / `memberships.planner_scope_type`.
   - `DELETE /api/assignments`: Closes assignment by setting `valid_to = effectiveDate` (or current date).

3. **Bulk Operational Move Endpoint (`POST /api/assignments/bulk-move`)**:
   - `POST /api/assignments/bulk-move`: Atomically updates multiple employees' area assignments.
   - Closes open `EMPLOYEE_AREA` assignments with effective dating.
   - Reassigns to `targetAreaId` (or unassigns if `null`).
   - Audited via `organization_audit_events` (`ASSIGNMENT_UPDATED`, metadata `action: 'BULK_MOVE_EMPLOYEES'`).

4. **Data Layer Enrichment (`api/_lib/data.js`)**:
   - `listMembers`: Enriched with `plannerScopeType`, `scopedAreaIds`, `scopedEmployeeIds`, and linked employee details (`employeeId`, `employeeName`, `employeeExternalId`, `employeeAreaId`).
   - `addMember`: Guarded against creating second OWNER (`OWNER_EXISTS`), supports initial planner scopes.
   - `updateMemberRole`: Directs owner mutations to `transferOwnership`, synchronizes planner scopes and operational assignments.
