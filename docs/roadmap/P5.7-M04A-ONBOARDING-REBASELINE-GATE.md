## 3. Explicit User vs Employee Separation (Anti-Implicit Employee Rule)

- **Rule:** A User (login credential + membership) is fundamentally distinct from an Employee (shift roster entity).
- Neither Owner nor Admin implicitly creates an Employee record simply by providing a name or email.
- The wizard explicitly asks: *"¿Esta persona también es empleado? Sí / No"*.
- Only when explicitly confirmed (`isEmployee: true`) is an Employee row created and linked (`user_id`).
- Verified by `api/onboarding/onboarding.test.js` (Scenario F) and UI form validation.

---

## 4. Progressive Disclosure & "Configurar más tarde"

- Step 4 (Structure) offers:
  1. *Sin estructura adicional por ahora* (jumps directly to summary)
  2. *Organizar por áreas de trabajo* (discloses Areas step)
  3. *Tengo planificadores que gestionan turnos* (discloses Planners step)
  4. *Lo configuraré más adelante* (jumps directly to summary)
- Any optional step (`areas`, `planners`, `employees`, `assignments`) displays a prominent *"Saltar este paso / Configurar más tarde"* action in the footer toolbar, allowing instant progression to summary.
