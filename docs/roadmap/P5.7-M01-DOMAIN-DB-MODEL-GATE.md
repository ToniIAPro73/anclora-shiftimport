## 1. Deliverables & Technical Changes

1. **Schema Audit**:
   - Inspected legacy single-area models: `employees.area_id`, `memberships.scoped_area_id`, `area_responsibles`.
   - Identified lack of temporal validity (`valid_from`, `valid_to`) and inability for planners to hold multi-area or explicit employee scopes.
2. **Assignment Model Decision**:
   - Established `operational_assignments` table with:
     - `assignment_type`: `'EMPLOYEE_AREA'`, `'PLANNER_AREA'`, `'PLANNER_EMPLOYEE'`.
     - `subject_id`: `employee_id` or `user_id`.
     - `target_id`: `area_id` or `employee_id`.
     - `valid_from DATE NOT NULL DEFAULT CURRENT_DATE`.
     - `valid_to DATE NULL` (NULL represents active ongoing assignment).
     - Range check constraint: `valid_to IS NULL OR valid_to >= valid_from`.
   - Partial unique indexes ensuring:
     - At most 1 active area per employee.
     - Non-duplicate active area assignments per planner.
     - Non-duplicate active employee assignments per planner.
3. **Planner Scope Representation**:
   - Added `planner_scope_type` column to `memberships`: `CHECK (planner_scope_type IS NULL OR planner_scope_type IN ('ORGANIZATION', 'AREAS', 'EMPLOYEES'))`.
4. **Audit Vocabulary Extension**:
   - Added `'OWNERSHIP_TRANSFERRED'`, `'PLANNER_SCOPE_CHANGED'`, `'ASSIGNMENT_CREATED'`, `'ASSIGNMENT_UPDATED'`, `'ASSIGNMENT_REMOVED'` to `organization_audit_events`.
5. **Backwards Compatibility & Backfill**:
   - Existing `employees.area_id` backfilled to active `'EMPLOYEE_AREA'` rows.
   - Existing `memberships.scoped_area_id` backfilled to active `'PLANNER_AREA'` rows and `planner_scope_type = 'AREAS'`.
   - Existing unassigned planners backfilled to `planner_scope_type = 'ORGANIZATION'`.
   - Legacy columns `employees.area_id` and `memberships.scoped_area_id` retained for backward compatibility.
6. **Migrations Verification**:
   - `0035_operational_assignments.sql` applied successfully to Neon development via `db/migrate.mjs`.
   - Fresh 35/35 migration verified in disposable schema via `scripts/verify-migrations-from-scratch.mjs`.
   - Migration unit tests in `db/migrations.test.mjs` (45/45 passing).
