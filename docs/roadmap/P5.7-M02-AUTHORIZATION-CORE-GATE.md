## 1. Deliverables & Technical Changes

1. **Backend Canonical Authorization Service (`api/_lib/authorization.js`)**:
   - Implemented `can(actor, action, target)` and `isTargetInScope(actor, target)` supporting all 19 canonical domain actions:
     `VIEW_TEAM`, `MANAGE_USERS`, `CREATE_ADMIN`, `CREATE_PLANNER`, `CREATE_EMPLOYEE`, `MANAGE_AREA`, `ASSIGN_EMPLOYEE`, `ASSIGN_PLANNER`, `PLAN`, `PUBLISH`, `IMPORT_SELF`, `IMPORT_TEAM`, `VIEW_SELF_SHIFT`, `EDIT_SHIFT`, `CREATE_REQUEST`, `VIEW_REQUEST`, `APPROVE_REQUEST`, `REJECT_REQUEST`, `TRANSFER_OWNERSHIP`.
   - Strict Anti-Self-Approval and Anti-Self-Rejection rules enforced for managers with associated employees.
   - Ownership Transfer permission reserved solely for the active OWNER with non-self target.
   - Role + Scope enforcement for planners across `ORGANIZATION`, `AREAS`, and `EMPLOYEES` scopes.
2. **Frontend Canonical Authorization Service (`src/lib/authorization.ts`)**:
   - Complete TypeScript mirror of the canonical authorization service and types (`Actor`, `Target`, `Action`).
3. **Enhanced Security Scope Resolution in `api/_lib/auth.js`**:
   - Loaded `planner_scope_type` and active `operational_assignments` for planners.
   - Extended `resolveAccessScope` to return typed scopes:
     - `ORGANIZATION`
     - `AREAS` (with `areaIds`)
     - `EMPLOYEES` (with `employeeIds`)
     - `SELF` (with `employeeId`)
   - Enhanced `resolveEffectiveAccessScope` to fail-closed (`SCOPE_UNAVAILABLE`) if `AREAS` or `EMPLOYEES` planner has 0 assignments, while permitting explicit `ORGANIZATION` planners even when active areas exist.
4. **Targeted Tests**:
   - `api/_lib/authorization.test.js`: 25 unit tests.
   - `src/lib/authorization.test.ts`: 7 unit tests.
   - `api/_lib/auth.test.js`: 23 unit tests (including new scope cases).
