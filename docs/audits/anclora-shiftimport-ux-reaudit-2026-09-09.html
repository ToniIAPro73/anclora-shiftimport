01Executive Summary

ShiftImport's core promise — turn an existing PDF/Excel/CSV schedule into a reviewable, structured calendar without writing anything until the organization confirms it — is real, live in production, and can be exercised end-to-end without an account through a "Continuar sin cuenta" (guest) entry point at /app. That path gave this audit genuine production browser evidence for Safe Import, the calendar workspace, the format-recovery assistant, and the future-shift routing decision — exactly the parts the September 5 audit could only partially exercise.

Biggest friction
At 390×844 the calendar grid and stats ribbon hide inside unlabeled horizontal-scroll containers — 4 of 7 weekday columns are invisible with no scroll affordance.
Biggest quick win
"Procesar archivo" stays visibly disabled after the file has already been parsed and results are showing.
Structural opportunity
None found — the desktop shell is sound. Extend its logic to mobile; don't add new chrome.
Overall assessment
6 of 7 retestable 2026-09-05 findings are fixed with real evidence. The mobile overflow issue is not — and it sits on the primary workspace.

Large parts of the authenticated, multi-tenant product — RBAC, Team management, bulk provisioning, Employee Portal, scheduling publish, import history — could not be exercised live this session. Not because they don't exist: this repository's own local-dev convention runs them behind vercel dev, which requires an interactive OAuth login this read-only audit will not perform on the user's behalf. That coverage gap, not a product defect, is why this report is Pass with gaps rather than Pass.

02What Changed Since the Previous Audit

The 2026-09-05 audit (36e7857) landed nine findings. The very next commits on development were 268489b docs(roadmap): add post-UX audit execution program and 13ab171 docs(agents): align role model with runtime — the team built a remediation program directly off that audit. Across the 76 commits since, the roles/scopes model was formalized (the P5.7 series: personas, RBAC, areas, planner scopes, ownership transfer, effective-dated assignments), alongside several UX-adjacent fixes: a dark/light theme consistency hotfix, input-focus preservation in the team modal, and ownership-transfer guardrails.

This audit did not trust that roadmap as evidence. It independently re-derived the product model from current code and browser behavior — see Section 10 for the line-by-line retest of each 2026-09-05 finding.

03Methodology Delta

  • SKILL.md and the runtime (ux_product_experience_review.py) both carry v1.5.0 behavior — finding_scope, browser-environment provenance, TOOL_COMPATIBILITY_GAP, deployed_surface_covered — while skill.yaml's version field still reads 1.4.0. Per CURRENT_INSTALLED_SKILL_WINS, v1.5.0 governs this report; the manifest lag is logged as an engineering note, not a blocker.
  • docs/VALIDATION.md does not exist in the skill package — not fabricated. Only docs/RELEASE_NOTES.md does.
  • This report follows the installed skill's actual Output Report v2 structure and vocabulary (finding scope, evidence levels, NOT_EVALUATED vs NOT_APPLICABLE, adaptive scorecards) rather than an older 46-section template, folding in the historical-regression-matrix and HTML-integrity requirements as non-conflicting extensions.
  • Composed AOS skills (accessibility, i18n, design-system, visual-regression) were not dispatched — this agent had no tool access to them this session. Reported as UNAVAILABLE, never silently treated as complete.
  • The repo's own documented local-dev path (vercel dev) requires an interactive OAuth login. A synthetic-seed database write was deliberately not executed, since without a working local API it would have produced a write with zero evidentiary benefit.

06Product Promise vs Observed Experience

Importar → revisar → comparar → confirmar → planificar → publicar → consultar → confirmar → solicitar cambios → aprobar → auditar.

Observed (guest scope, production): import → detect → assisted row-matching when ambiguous → editable preview → explicit historical-vs-draft routing decision → gated confirm with a plain-language reason.

The promise holds for the segment this audit could observe directly. The row-matching assistant states plainly why it needs input — "No se encontró ninguna fila que coincida de forma fiable con tu perfil. No se importará nada hasta que lo resuelvas." — and the future-shift routing choice is surfaced as a decision, not a silent default.

The planificar → publicar → auditar segment could not be independently re-verified in the browser this session (AUTH_BLOCKED); it rests on code inspection and the product's own extensive test documentation — legitimate, but weaker evidence than direct observation.

08Application Shell & Responsive

Desktop (1440×900): a slim role-aware left rail ("Operación": Calendario / Importar turnos / Añadir turno), a compact top bar, and the calendar as an unmistakably dominant primary workspace — no stacked navigation rows, no competing chrome. This matches the skill's premium doctrine: disciplined hierarchy, restrained surfaces, nothing decorative.

Mobile (390×844): the same screen becomes a nested horizontal-scroll region. Visually, only 3 of 7 weekday columns and a sliver of a 4th are visible, with no scrollbar, arrow, or fade cue. See Finding F-2026-09-09-01.

09Light / Dark & i18n

Both themes render the guest calendar without loss of hierarchy or contrast in either direction — light mode reads as considered, not "dark bolted backwards." Numeric stat columns, calendar cell borders, and the selected-day state all stayed legible in both.

ES↔EN was exercised live on the guest calendar: "Septiembre 2026" → "September 2026," sidebar and stat labels translated, no raw i18n keys or mixed-language fragments observed in the screens visited. This is a narrow slice of the full i18n surface — the authenticated app's settings/team/import-history strings were not re-verified live this session.

12What Works Well

  • Pre-write transparency in Safe Import. The system states what it found, what it's unsure about, and what will happen if the user proceeds — including an explicit historical-vs-draft choice for future shifts. Do not break.
  • Guest/local-first mode as a genuine, low-friction way to experience the real product — same calendar, same import pipeline, same assistant, not a stripped demo. Do not break.
  • Format-recovery assistant — plain-language reason, one-click resolution, persistent "remember this format" option. Do not break.
  • Plan-gate pattern in Members — disabling the whole form and explaining why, before the user has typed anything. Do not break.
  • Desktop shell restraint — compact header, role-aware sidebar, calendar-first in both themes. Do not break as the mobile fix lands — it should not add the chrome the desktop shell currently avoids.

13Findings — Product UX / Access

F-2026-09-09-01 CriticalP1 measured_browser · production scope: product_ux

Calendar and stats ribbon are hidden inside unlabeled horizontal-scroll containers at mobile widths

Journey
Calendar view (core, frequent) — guest workspace /app
User type
Any authenticated or guest user on a phone
Friction
Responsive, discoverability
Evidence
390×844, dark, es-ES, shiftimport.anclora.com/app. .month-grid-shell → scrollWidth 780 / clientWidth 370. .totals-ribbon → scrollWidth 1135 / clientWidth 370. No scrollbar, arrow, or edge fade rendered.
Current behavior
Each region is wrapped in its own horizontally-scrollable container sized for its full desktop column count, with no mobile reflow and no visible signal that content exists sideways.
Root cause
A desktop-oriented fixed-column layout placed inside overflow-x without a narrow-viewport reflow or a scroll affordance.
Why it matters
The calendar is the product's primary workspace. A phone user cannot see or add shifts for Thursday–Sunday without accidentally discovering a swipeable region.
Recommended change
On narrow viewports: a single-column/day-list view with a week switcher, or a swipeable week strip with a visible indicator (dots, partial next-cell reveal, edge gradient). Collapse the stats ribbon to current-period totals with a "show more" disclosure.
Effort / Risk
Medium / Low — additive responsive change, no desktop behavior change
Do not break
Desktop shell's current calendar dominance and compact chrome
Given a user opens the calendar at a 390px-wide viewport When the month view renders Then all seven weekday columns (or an equivalent day-by-day view) are reachable without an undiscoverable, unlabeled horizontal scroll And the stats ribbon's key totals are visible without horizontal scrolling And no functionality available at 1440px is removed at 390px

14Supporting Engineering Findings

Scope: ENGINEERING_SUPPORT — visible for the record, does not affect the scorecards above.

  • skill.yaml version lag. Declares 1.4.0; SKILL.md and the runtime already implement v1.5.0 behavior. Recommend bumping the manifest field.
  • .env.example documentation drift. States "hoy no hay auth ni aislamiento por usuario," true only for guest/local-storage mode — the multi-tenant Postgres-backed org layer with real auth/RBAC is substantial and real. A reader of only this file would underestimate the current auth model.
  • Local API dev loop requires interactive login. vercel dev — this repo's own documented way to run /api/* locally — starts an OAuth device-flow with no documented non-interactive path for a read-only agent/CI-style audit. This is the direct cause of this session's authenticated-coverage gaps.

18Limitations & Gaps

  1. No authenticated multi-tenant browser coverage. vercel dev requires an interactive OAuth login this agent will not perform. Everything downstream of a real org/role account rests on code inspection and product documentation, not direct observation. This is the single largest gap in this audit.
  2. No composed AOS skills executed — accessibility, i18n, design-system, and visual-regression checks were not dispatched this session.
  3. Tablet and mobile-landscape viewports not attempted.
  4. Unknown-format/OCR recovery path not re-run live; evidence is documentation-only.
  5. Import History / Auditability screen was not located in guest scope — unknown whether it's account-gated or elsewhere.
  6. The database seed script was deliberately not executed. It would have written synthetic data to a non-production database for zero evidentiary benefit, since the local API it would have supported could not start without an interactive login.

19Final Answers

Can an Owner, Admin, Planner or Employee complete their tasks simply and safely today?

For the paths this audit could observe directly — yes, on desktop. Not reliably on a phone, because of F-2026-09-09-01. For the authenticated multi-tenant paths, the code and the product's own extensive test suite say yes; this audit could not independently confirm it live.

Does ShiftImport feel premium, or is complexity creeping in?

Premium, on the evidence gathered: the desktop shell stayed calm and calendar-first in both themes, Safe Import states its own decisions in plain language, and no generic-SaaS visual patterns were observed. The mobile calendar defect is the one place the experience currently falls short of that standard.

What's fixed, what remains, what regressed, what's new?

6 of 7 retestable findings fixed with real evidence; 1 (mobile overflow) still present; nothing regressed; two new findings surfaced this session — one product, one process.

Is the difference between audits a real improvement, a coverage difference, a methodology shift, or all three?

All three, and they shouldn't be conflated. The six fixes are real, code-and-browser-verified improvements. The lower total finding count is not evidence the product broadly improved — it reflects genuine fixes, a narrower live-authenticated coverage this session (documented above), and a stricter v1.5.0 evidence model that refuses to grade what it couldn't measure.

Read-only audit. No application code, configuration, or database state was modified. One local dev server (vite / proxy-server.mjs) was started and stopped for comparison purposes; no database writes occurred.
